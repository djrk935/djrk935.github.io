AI & Backend2026Personal project

Coach K

An AI strength coach that remembers each athlete and grounds its programs in real training science, with citations.

Goal

A coach that keeps context across sessions and backs its programming with sources, rather than generic chatbot advice.

What I built

  • Version 1 on Cloudflare Workers: form analysis from about 5 keyframes extracted in the browser (the video never uploads), long-term memory through a per-user vector index, and branded program PDFs.
  • Version 2 on FastAPI, PostgreSQL with pgvector and LangGraph, with a React front end and a native iOS app.
  • An idempotent ingestion pipeline (SHA-256 dedupe, transactional bulk loads) that parsed 7 textbooks into 7,201 embedded chunks and kept 2,568 tables as structured records for targeted retrieval.
  • A PostgreSQL schema over 8 versioned migrations: append-only JSONB profile versions, daily readiness facts and set-level workout logs, with B-tree, GIN and HNSW indexes.

Results

  • Training metrics (ACWR, Epley estimated 1RM, automatic PR detection) for a progress dashboard. ACWR stays hidden until 2 weeks of data exist, so it can’t raise false overtraining alerts.
  • Deployed to DigitalOcean, including debugging live PostgreSQL connection errors in psycopg.

Python, FastAPI, PostgreSQL, pgvector, LangGraph, React, Docker, Cloudflare Workers

Data Automation2026University Co-op

Game-Day Restock Pipeline

One pick-and-reorder list for game days, built from three systems that each held part of the picture.

Problem

Bin inventory lived in ShipHawk, sales in Shopify and floor targets in NetSuite, and a once-a-day inventory sync left a gap between recorded counts and what was actually on the floor.

What I built

  • A Python Azure Function, orchestrated with Power Automate, that joins ShipHawk bin inventory, Shopify sales and NetSuite floor targets into game-day pick and reorder lists.
  • A live-floor metric: the last sync count minus Shopify sales since that sync, to close the daily gap.

Results

  • Output reconciled against a 15,114-row production export.
  • Covered by 6 data-quality unit tests.
  • Pitched to stakeholders.

Python, Azure Functions, Power Automate, Shopify Admin API, NetSuite

Internal University Co-op project, so the code isn’t public.

Systems2026Personal project

Cinnabar (working name)

A permissively licensed PlayStation 2 emulator for Apple Silicon, written from scratch in C++.

What I built

  • An R5900 (Emotion Engine) interpreter: MIPS-III integer, branch and load/store instructions, 64-bit operations, COP0 including ERET, and the R5900’s LQ and SQ.
  • Branch delay slots and branch-likely annulment, implemented and tested.
  • A memory bus mapped like the PS2’s: 32 MiB of RAM, a write-protected 4 MiB BIOS region, EE and GS registers, IOP RAM and scratchpad.
  • A disassembler that never guesses: unknown encodings render as .word.

Results

  • 112 automated checks, 0 failures.
  • A hand-assembled loop summing 1 to 10 retires exactly 54 instructions and returns 55.
  • Unimplemented hardware halts and gets counted instead of silently corrupting state.

C++, CMake, Ninja

Early bring-up. No BIOS is bundled, the name is provisional and the code isn’t public yet.

Process Automation2026University Co-op

Gift Card Email Logger

A Power Automate flow that ended manual data entry for gift card emails after the move to Shopify.

Problem

After the switch to Shopify, gift card notification emails had to be copied one by one into tracking spreadsheets.

What I built

  • A cloud flow that parses Shopify HTML emails and pulls each 16-character code with anchored string parsing on the last 19 characters.
  • Server-side OData filtering that blocks duplicates before they’re written.
  • A log entry for every run.

Results

  • Manual data entry eliminated.
  • Hardened after real emails started putting the code and its label on one line and broke production.
  • Earned an Achiever peer award.

Power Automate, Excel, OData

Internal University Co-op project, so the flow isn’t public.
